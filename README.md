# 함정길잡이

함종의 역할과 장비, 함정사업 획득절차를 배우는 React·TypeScript·Vite 학습 웹입니다. 학습은 로그인·백엔드·실시간 AI 호출 없이 동작하며, 피드백은 외부 설문 서비스 Tally에 저장합니다.

서비스: https://silbet.github.io/naval-acquisition-learning/

친구·후임 개발자에게 전달할 때는 [인수인계 안내](docs/HANDOFF.md)를 먼저 확인하세요. 최신 코드는 기본 브랜치 `main`에 있으며, `main` 변경이 GitHub Pages에 자동 배포됩니다.

## 학습 흐름

단원 선택 → 5·10·20문항 선택 → 풀이 → 채점 → 해설·출처 확인 → 오답 재도전. 별도 동의 체크 없이 시작합니다. 학습 종료 확인, 키보드 1–4/Enter, 모바일 화면, 새로고침 복구, 최근 100회 기록을 지원합니다.

## 문제은행과 출제 정책

현재 출제 문항은 305개입니다. 함종 전용 125문항(구축함·호위함·기뢰전함 각 21, 상륙함·잠수함 각 20, 지원·구조함 22), 공통 업무 상황형 60문항, 방위사업 용어형 120문항입니다. 등록된 공개 출처는 32개입니다. 기존 공통 기초 24문항은 `retired`로 보관하고 출제하지 않습니다.

| 카테고리                   | 단원                                                  | 출제 범위                      |
| -------------------------- | ----------------------------------------------------- | ------------------------------ |
| 함정사업 문제              | 구축함, 호위함, 상륙함, 잠수함, 기뢰전함, 지원·구조함 | 선택한 함종만 5·10·20문항      |
| 공통 업무 문제 (`/common`) | 획득·소요 실무, 계약관리 실무, 사업관리·시험평가, 방위사업 용어 퀴즈 | 선택한 업무 단원만 5·10·20문항 |

함종 부족분을 공통으로 채우지 않습니다. 선택 단원의 고유 개념이 부족하면 해당 문제 수를 비활성화합니다. 모든 단원은 고유 개념 20개 이상을 확보했습니다. 오답 재도전도 해당 단원의 틀린 문항만 대상으로 합니다.

역할·임무, 장비·원리, 획득·사례, 실무·상황, 용어·개념 주제를 순환해서 뽑고 최종 순서를 섞습니다. 같은 `concept`의 유사 문항은 한 회차에 하나만 출제합니다. 서로 다른 회차 사이의 반복까지 차단하지는 않습니다. 공통 상황형 60문항과 용어형 120문항은 자체 제작이며 실제 자격시험 기출문제가 아닙니다. 상황형은 업무 처리 순서, 용어형은 정의와 유사 용어의 차이를 해설에서 제공합니다. 근거와 원문 출처는 두 형식 모두 확인할 수 있습니다.

[문제 구성 분석과 보강 내역](docs/content-analysis.md)에 기존 문제점, 단원별 구성, 출처 활용 원칙을 정리했습니다.
2026.10.25. 개편의 근거·문항 구성·관리 원칙은 [공통 실무 상황형 문제 안내](docs/business-scenarios.md)를 확인하세요.
공통 업무 마지막 단원의 구성은 [방위사업 용어 퀴즈 안내](docs/terminology-quiz.md)를 확인하세요.

## 실행과 검증

Node.js 24 LTS 권장.

```sh
npm ci
npm run dev
npm run validate:data
npm test
npx playwright install chromium
npm run test:e2e
npm run build:pages
npm run test:pages
npm run preview -- --mode pages
```

개발 주소는 `http://127.0.0.1:5173`입니다. 일반 정적 호스트용 빌드는 `npm run build`이며 SPA fallback이 필요합니다. Pages 빌드는 `/naval-acquisition-learning/` 자산 경로와 해시 라우터를 사용해 직접 진입·새로고침을 지원합니다.

## 콘텐츠 관리

- 기존 문항과 타입: `src/data.ts`
- 확장 출처·문항: `src/content-expansion.ts`
- 공통 실무 상황형·공식 규정 근거: `src/business-content.ts`
- 방위사업 용어 120개·정의/상황·혼동 용어·근거: `src/terminology-content.ts`
- 담당자 검수 기록·사용 중단: `src/reviews.ts`
- 출제 구성과 세션: `src/domain.ts`

새 문항은 명시적인 개념 ID를 부여합니다. 같은 학습목표를 표현만 바꾼 문제는 같은 `concept`를 사용합니다. 기존 문항 배열의 순서를 바꾸면 ID가 달라지므로 기존 문항을 중간 삽입하거나 재정렬하지 않습니다. 확장 문항은 개념 이름을 기반으로 안정적인 ID를 가집니다.

출처는 방위사업청으로 제한하지 않습니다. 현재 방위사업청, 미·영 해군, 영국 정부, 한화 공식 기술 소개를 사용합니다. 발행기관·제목·원문 URL·게시일(확인한 경우)을 기록합니다. 검증 스크립트의 허용 호스트에 출처를 명시적으로 등록합니다. 향후 신뢰할 수 있는 언론·방산 전문기사도 출처와 근거를 확인한 뒤 추가할 수 있습니다. 해외 함정의 구성은 해당 국가·함정명을 문항에 명시합니다. 기사 전체나 홍보 문구를 복사하지 않고 확인된 사실로 질문·해설을 작성합니다. 예정 일정과 완료 사실을 구별합니다.

`published`는 서비스 공개, `verified`는 개별 담당자 검수 기록이 있는 문항입니다. 사용자가 기존 문제에 대한 담당자 검토와 역할 문항 보강 의견을 전달했고 이를 반영해 정식 학습 흐름으로 전환했습니다. 검수자·승인 문항 ID·날짜가 없는 개별 이력을 임의로 만들지 않습니다. 이번 추가 문항도 공개되지만 사람 검수 완료를 주장하지 않습니다. `retiredIds`에 등록한 문항은 즉시 출제에서 제외합니다.

## 저장

진행 회차는 `hamjeong.session.v2`에 저장됩니다. 문항 구조가 달라 이전 v1 진행 회차는 이어서 사용하지 않습니다. 완료 기록은 기존 `hamjeong.history.v1`을 그대로 읽어 보존하며 이전 구분 배지는 표시하지 않습니다. 같은 탭의 새로고침을 복구하고, 기록 삭제 기능을 제공합니다. 다른 브라우저·기기와 동기화하지 않습니다.

## 피드백 접수

Pages의 `/naval-acquisition-learning/#/feedback`에 로그인 없이 제출하는 Tally 양식을 삽입합니다. 학습 기록과 달리 제출한 의견은 Tally 서버에 저장되어 운영자 계정에서 확인할 수 있습니다. 이름·연락처는 수집하지 않으며 의견은 공개 게시하지 않습니다. 제출 완료 화면을 확인해야 접수된 것이며, 폼을 열거나 내용만 작성한 상태를 저장 성공으로 표시하지 않습니다.

설정은 `src/feedback-settings.json`의 공개 `tallyFormId`입니다. API 키나 비밀번호를 넣지 않습니다. 개발·테스트 시 `VITE_TALLY_FORM_ID`로 대체할 수 있고, 비어 있거나 잘못된 ID면 접수 준비 중 안내만 표시합니다. 폼이 차단되는 브라우저를 위해 새 탭으로 여는 링크도 제공합니다.

운영자는 [Tally 폼 관리](https://tally.so/forms/X5lb1e/submissions)에서 본인 계정으로 로그인해 의견을 확인합니다. 무료 요금제의 기본 폼·응답 저장·사이트 삽입만 사용하며, 유료 구독·브랜딩 제거·커스텀 도메인은 사용하지 않습니다. 자세한 설정과 저장 확인 방법은 [피드백 운영 안내](docs/feedback.md)를 확인하세요.

## 배포와 Git

기능 브랜치 → 기능별 한글 커밋 → 푸시 → `[Feature] ...` PR 순서를 따릅니다. 최신 구현과 문항 보강은 `main`에 통합했습니다. 새 작업은 최신 `main`에서 브랜치를 만들고 PR 대상도 `main`으로 지정합니다.

GitHub Actions의 `pages.yml`은 단위 테스트·Pages 빌드·브라우저 테스트 후 배포합니다. 자동 배포 대상과 github-pages 환경의 허용 브랜치는 `main`입니다. 기능 브랜치는 검증 후 PR을 통해 main에 병합합니다. 수동 실행도 main에서 실행해야 합니다. 별도 호스팅 계정·API 키는 필요하지 않습니다.

기관의 공식 교육·평가 서비스는 아닙니다. 학습 기록은 로컬에만 저장하며 서버 점수 검증은 제공하지 않습니다. 실험적 WebMCP는 지원 브라우저에서 단원 목록과 문제 수만 제공합니다.
