# 함정길잡이

방위사업청 신규 직원이 함정사업 획득절차를 짧은 퀴즈로 학습하는 반응형 웹입니다. React·TypeScript·Vite로 만든 정적 웹이며 앱 로그인, 백엔드, 외부 AI API 없이 동작합니다. GitHub Pages에서 공개 시연용으로 배포합니다. 방위사업청의 공식 서비스가 아닙니다.

## 현재 구현

- 공통 절차 + 구축함·호위함·상륙함·잠수함·기뢰전함·지원·구조함 7개 단원
- 5·10·20문제, 중복 없는 무작위 출제와 균등한 정답 위치
- 마지막 제출 후 점수·항해 등급, 출처와 오답 해설, 오답만 재도전
- 새로고침 복원, 이동 시 종료 확인, 키보드 1–4와 Enter
- 획득절차 맵, 익명 로컬 학습 기록, 취약 단계 복습
- 데이터 검증, 채점·출제 테스트, 데스크톱·360px 모바일 E2E

## 시작

Node.js 22.12 이상 또는 24 LTS가 필요합니다.

```sh
npm ci
npm run dev
npm run validate:data
npm test
npx playwright install chromium
npm run test:e2e
npm run build
npm run preview
```

개발 기본 주소는 `http://127.0.0.1:5173`입니다. 첫 화면에서 단원을 선택하고 **시연용 문제로 연습하기**를 체크한 후 시작합니다. 배포 사이트는 URL을 아는 누구나 접근할 수 있는 공개 시연입니다.

## 콘텐츠 상태와 계획서 대비 차이

고유 문항은 **62개**, 공식 출처는 **12개**입니다. 공통 절차 20개, 구축함·호위함·상륙함·잠수함·기뢰전함 사례 각각 6개, 지원·구조함 사례 12개입니다. 함종별 풀은 공통을 포함해 26개(지원·구조함 32개)입니다. 한 회차에 중복은 없지만 다른 함종 학습에서는 공통 문제가 다시 나올 수 있습니다. 20문제 모드는 사례 최대 10개와 나머지 공통으로 구성됩니다. 공유 문제를 함종별 신규 문항으로 세지 않습니다.

문항은 공개 검색 결과의 방위사업청 본문을 AI가 대조한 **초안(draft)**입니다. 일부 원문은 자동 접속 제한·시간 초과가 있어 출처 링크의 사람 재확인이 필요합니다. 사람 검수자가 없는데 `verified`로 표시하지 않았습니다. 일반 모드는 검수 완료 문제만 출제하며, 현재 정식 문제 수는 0개입니다. 별도로 동의한 시연 모드에서만 초안을 풀 수 있습니다. 따라서 계획서의 **단원별 사람 검수 완료 20개** 조건은 아직 미충족입니다.

함종마다 다른 획득절차가 존재한다고 가정하지 않습니다. 공통 개념과 공개 사업사례를 구분하며, 절차 맵은 연구개발 방식의 학습용 요약입니다. 지원·구조함은 군수지원함과 강화도함 잠수함구조함 사례를 포함합니다. 과거 보도자료의 예정일과 실제 인도 발표일을 구별합니다. 오답 보기는 학습용으로 작성한 선택지이며 공식 사실로 인용하지 않습니다.

스타일은 Tailwind 대신 로컬 CSS 디자인 토큰으로 구현했습니다. 서버가 필요 없는 요구사항을 유지하고 React Router·Zod·Vitest·Playwright를 사용합니다. 실시간 AI 생성은 없으며 AI 활용은 개발 및 출처 기반 문제 초안 작성입니다. 콘테스트의 AI 심사기준과의 적합성은 별도 확인이 필요합니다.

## 문제를 검수하고 추가하는 방법

1. `src/data.ts`의 `sources`에서 방위사업청 원문 URL을 엽니다. 공개자료의 게시 시점과 현재 내용이 맞는지 확인합니다.
2. `rows`의 질문·정답(세 번째 값)·오답 3개·해설을 원문과 대조합니다.
3. 승인된 문제 ID만 `src/reviews.ts`에 검수자 식별명과 검수일을 기록합니다. 기록이 없는 문제는 계속 draft입니다.
4. `npm run validate:data`로 유일한 ID, 보기, 출처 호스트, 검수기록을 확인합니다.
5. 일반 모드에서 해당 단원 문제가 충분할 때 5·10·20 선택지가 활성화되는지 확인합니다.

검수자는 실제 검수한 사람만 기록합니다. AI 이름으로 사람 검수를 대체하거나 날짜를 소급하지 않습니다. 원문 변경·삭제 시 해당 문항을 재검수하고, 사용 중단은 `retiredIds`에 ID를 추가합니다. 문항 수정은 배포 버전 변경과 함께 진행하며 기존 세션은 원문 데이터와 맞지 않으면 안전하게 초기화됩니다.

출처는 `https://www.dapa.go.kr` 또는 `https://dapa.go.kr`만 허용합니다. 앱은 런타임 크롤링, 사용자 파일 업로드, 외부 분석 전송을 하지 않습니다. 출처 원문은 사용자가 링크를 누를 때 새 창으로 열립니다. 서버 점수 검증이 없는 자율학습 도구이므로 공식 시험·인사평가에 사용하지 않습니다.

## 저장과 오류 처리

- 진행 중 회차는 `sessionStorage`의 `hamjeong.session.v1`에 저장됩니다. **같은 탭의 새로고침을 복구**하며, 탭을 완전히 닫은 뒤 복구는 보장하지 않습니다.
- 완료 기록은 `localStorage`의 `hamjeong.history.v1`에 최대 100회 저장됩니다. 다른 기기·브라우저와 동기화하지 않습니다.
- 이름·사번·소속을 수집하지 않습니다. 공유 PC에서는 학습 기록 지우기를 사용할 수 있습니다.
- 저장소 사용이 차단되면 퀴즈 시작 단계에서 이유를 안내합니다. 잘못된 JSON·버전·보기·정답·현재 위치는 복원하지 않습니다.

## 배포

공개 주소: https://silbet.github.io/naval-acquisition-learning/

`npm run build:pages`의 `dist/`를 GitHub Actions에서 업로드합니다. 저장소 Settings → Pages → Source는 **GitHub Actions**입니다. 별도 AWS·Vercel 계정, 유료 도메인, API 키는 필요하지 않습니다.

Pages 빌드는 `/naval-acquisition-learning/` 자산 경로와 HashRouter를 사용합니다. 주소 예시는 `#/setup/destroyer`이며 직접 접속·새로고침에도 404가 나지 않습니다. 로컬 개발 및 일반 빌드는 BrowserRouter입니다. 다른 호스트에 일반 빌드를 설치할 경우 SPA fallback이 필요합니다.

```sh
npm run build:pages
npm run test:pages
npm run preview -- --mode pages
```

`.github/workflows/pages.yml`은 테스트·빌드 → Pages 전용 브라우저 테스트 → 배포 순으로 실행합니다. 현재 `main`과 `feat/ship-acquisition-learning-web`의 푸시가 배포를 시작합니다. **기능 브랜치의 시연을 먼저 배포하며 Draft PR을 자동 병합하지 않습니다.** 최초 PR 병합 후에는 해당 기능 브랜치를 workflow와 github-pages 환경 허용 목록에서 제거하고 `main`만 운영하는 것을 권장합니다. 다른 작업 브랜치는 검증 CI만 실행합니다. 두 배포 대상 브랜치 중 마지막으로 성공한 배포가 공개 사이트를 갱신합니다.

기존 Sites 설정과 다른 호스트 전용 헤더·리다이렉트 파일은 제거했습니다. Pages는 이 파일들로 사용자 정의 보안 헤더를 적용하지 않습니다. 공개 소스·문항만 올리며 내부 문서, 개인정보, 비공개 사업정보, 인증키를 추가하면 안 됩니다. 이름·사번·소속은 수집하지 않지만 호스팅 제공자의 접속 로그까지 없다는 뜻은 아닙니다. 기관망 접근 허용과 콘테스트 공개 시연 허용 여부는 담당 부서에 확인해야 합니다. 이 배포는 기관 보안 승인이나 공식 교육서비스 승인을 의미하지 않습니다.

오류 발생 시 직전 정상 커밋에서 기능 수정 브랜치를 만들고, 검증 → PR → 승인·병합 → 재배포 순으로 복구합니다. 비밀정보가 잘못 공개된 경우 파일 삭제만으로 저장소 이력이 지워지지 않으므로 즉시 담당자에게 알리고 별도 조치합니다.

## Git

기능 브랜치에서 기능별 한글 커밋을 작성하고 푸시 후 `[Feature] ...` 형식 PR을 생성합니다. 원격 저장소: https://github.com/Silbet/naval-acquisition-learning

## 3분 시연

1. 홈에서 공통 절차와 함종별 단원을 설명합니다.
2. 구축함 → 시연 동의 → 5문제를 고릅니다.
3. 1–4번 선택과 Enter로 풀이하고 중간에 새로고침 복원을 보여줍니다.
4. 점수와 등급을 확인한 뒤 오답 복습에서 공식 출처를 엽니다.
5. 오답 재도전, 절차 맵, 학습 기록을 보여줍니다.

## 남은 콘텐츠 작업

- 실제 담당자의 문항·해설 검수와 승인 기록
- 단원별 고유 문항 확대(현재 공통 공유 방식이며 함종별 20개 고유 문항 조건은 미충족)
- 업무 용어로 보완한 오답 보기의 담당자 검토 및 단계별 난이도 분류
- 공식 교육자료로 사용할 경우 해당 시점의 절차·규정 재확인

실험적 WebMCP `list_learning_units`는 지원 브라우저에서 단원 목록만 읽습니다. 미지원 브라우저에서는 일반 웹 기능에 영향이 없습니다.
